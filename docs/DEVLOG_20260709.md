# 开发日志 2026-07-09

## 调度器转换为真实业务逻辑

### 背景

原型阶段调度器包含模拟逻辑：ready 任务 5 分钟后自动推进到 in_progress，假装有员工接单。现在员工工作台已完整可用，真实员工通过 Socket IPC 接单/提交/阻塞，调度器只应处理纯时间驱动的业务。

### 删除

| 逻辑 | 原因 |
|------|------|
| ready → in_progress (5min 自动) | 模拟员工接单，员工工作台已支持真实接单 |

### 新增

| 逻辑 | 条件 | 动作 |
|------|------|------|
| ready → scheduled | planned_start 被推迟到未来（重新排程后） | 回退到已排程 |
| 逾期检测 | is_overdue 且未归档/完成 | 写入操作日志 + 发射 TASK_OVERDUE 事件 |

### 修复

- 每任务独立 try/except，单任务日志写入失败不会中断整轮 tick
- 逾期去重：`_notified_overdue` 集合记录已通知 ID，同次运行不重复

## 状态线程安全

AppState 被三个线程同时访问：scheduler 后台线程、SocketServer 工作线程、Flet asyncio 主线程。之前无任何锁保护。

- 添加 `threading.RLock()` 保护 `_tasks` / `_task_order` / `_columns` / `_aircraft`
- 持锁方法：`create_task`, `update_task`, `move_task`, `delete_task`, `to_dict`, `load_from_dict`
- 用可重入锁（RLock）而非 Lock，因为 `_notify()` 回调可能调回 state 读取方法

## 日志补全

### 新增日志类型

| LogType | 说明 |
|---------|------|
| ACCEPT_TASK | 员工通过工作台接单 |
| AI_PROPOSAL_REJECT | AI 提案被拒绝 |

### Socket 端补全

员工工作台通过 Socket IPC 接单/提交验收时只有 `log.info()` 文本日志，无结构化 LogEntry。现补全：
- `_handle_accept` → `LogType.ACCEPT_TASK` + 员工 ID/姓名
- `_handle_submit` → `LogType.SUBMISSION` + 工时/交接班日志

### AI 提案补全

AI 幽灵卡拒绝操作补全 `LogType.AI_PROPOSAL_REJECT`。

## 机队状态实时计算

### 问题

飞机数据（open_defects、overdue_tasks_count、status）存在 JSON 里从不更新。实际 7 个逾期任务但 B-9076 显示 0。

### 修复

`get_fleet_summary()` 完全从实际任务实时计算：
- 飞机列表：存储的飞机 ∪ 任务中引用的机号

- 飞机状态：有 AOG 任务→AOG，有未关闭任务→维修中，无→运行中
