# 开发日志 2026-07-09

## 调度器转换为真实业务逻辑

### 背景

原型阶段调度器包含模拟逻辑：ready 任务 5 分钟后自动推进到 in_progress，假装有员工接单。现在员工工作台已完整可用，真实员工通过 Socket IPC 接单/提交/阻塞，调度器只应处理纯时间驱动的业务。

### 删除

| 逻辑 | 原因 |
|------|------|
| ready → in_progress (5min 自动) | 模拟员工接单，员工工作台已支持真实接单 |

### 新增

| 逻辑 | 条件 | 动作 |
|------|------|------|
| ready → scheduled | planned_start 被推迟到未来（重新排程后） | 回退到已排程 |
| 逾期检测 | is_overdue 且未归档/完成 | 写入操作日志 + 发射 TASK_OVERDUE 事件 |

### 修复

- 每任务独立 try/except，单任务日志写入失败不会中断整轮 tick
- 逾期去重：`_notified_overdue` 集合记录已通知 ID，同次运行不重复

## 状态线程安全

AppState 被三个线程同时访问：scheduler 后台线程、SocketServer 工作线程、Flet asyncio 主线程。之前无任何锁保护。

- 添加 `threading.RLock()` 保护 `_tasks` / `_task_order` / `_columns` / `_aircraft`
- 持锁方法：`create_task`, `update_task`, `move_task`, `delete_task`, `to_dict`, `load_from_dict`
- 用可重入锁（RLock）而非 Lock，因为 `_notify()` 回调可能调回 state 读取方法

## JSON → SQLite 持久化

### 背景

JSON 文件三个痛点：不支持并发写、全量读写慢、无查询能力。

### 方案

```sql
CREATE TABLE tasks (id, title, status, priority, ... 40 columns);
CREATE TABLE task_order (col_id, task_id, position);
CREATE TABLE columns_config (id, title, wip_limit, ord, visible);
CREATE TABLE aircraft (registration, model, status, ...);
```

- WAL 模式支持并发读写
- `to_dict()` / `load_from_dict()` 接口不变，业务代码零改动
- 自动保存/防抖/EventBus 监听全部保留
- 迁移脚本 `scripts/migrate_to_sql.py`（独立，不侵入 app）
- app.py 仅改一行：`board_state.json` → `board_state.db`

## 撤销/重做 (Ctrl+Z/Y)

### 架构

Command 模式栈，UndoManager 全局单例：

```
操作记录:
  move_task  → push("移动 → triage", undo_fn, redo_fn)
  update_task → push("编辑 title", undo_fn, redo_fn)
  create_task → push("创建任务", undo_fn, redo_fn)
  delete_task → push("删除任务", undo_fn, redo_fn)

Ctrl+Z → undo_stack.pop() → undo_fn() → redo_stack.append()
Ctrl+Y → redo_stack.pop() → redo_fn() → undo_stack.append()
```

### 关键设计

- `_replaying` 标志：撤销/重做执行期间禁止重复记录
- 200 步上限
- 分组支持（begin_group / end_group）
- 新操作自动清空 redo 栈
- 撤销失败不崩溃（catch + log）

### State 钩子

| 操作 | 记录时机 | undo | redo |
|------|---------|------|------|
| move_task | 移动后 | 移回原位+旧状态 | 移到新位+新状态 |
| update_task | 更新后 | 恢复旧值 | 应用新值 |
| create_task | 创建后 | 删除任务 | — |
| delete_task | 删除前快照 | 恢复任务 | 重删 |

### Toast 反馈

- 撤销/重做成功 → "撤销: 移动 → triage"
- 无操作 → "没有可撤销的操作"

### 附带修复

- `task.to_dict()` 容错 string 字段（priority/task_type/status 可能为字符串非枚举）
- `CommandBar.show()` 改用 `page.open()`
