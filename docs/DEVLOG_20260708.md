# 开发日志 2026-07-08

## Socket IPC 架构重构

### 背景

文件轮询 IPC 存在根本性问题：
- `employee_state.json` 只在 `save()` 时写入（5s 防抖）→ 子进程最长 6s 数据不一致
- 同一份数据 6 个副本（1 主内存 + 2 磁盘文件 + 3 子进程内存）
- 连续操作时防抖 Timer 不断重置 → 文件永不写入 → 永久不一致

### 方案

TCP Socket 替代文件 IPC：

```
主进程 socket_server (localhost:随机端口)
  ├─ 子进程连接 → get_state() → 内存加载
  ├─ 子进程轮询 → hash (轻量) → 变更时 pull state
  ├─ 子进程写命令 → 服务端执行 + save + 返回新 state
  └─ 主进程关闭 → close() → 子进程 poll 检测断开 → window.close()
```

### 新增

| 文件 | 行 | 职责 |
|------|-----|------|
| `app/core/services/socket_server.py` | ~250 | 主进程 TCP server（JSON 行协议） |
| `app/core/services/socket_client.py` | ~200 | 子进程 TCP client（hash 轮询+命令） |

协议：`{"action":"get_state|hash|accept_task|block_task|submit_task","params":{...}}` ↔ `{"ok":true,"data":{...}}`

### Bug 修复记录

1. **close() 线程内 join 自己死锁** — `close()` 在 poll 线程的 `on_disconnect` 回调内调用 `join()` → `RuntimeError: cannot join current thread`。修复：`join` 前检查不是当前线程；`_do_close` 中不调 `close()`。

2. **空白/卡死窗口** — `SocketClient()` 构造时同步阻塞 `main()` → Flet 窗口已创建但 UI 从未初始化。修复：三个子进程统一改为先渲染 UI（显示"正在连接"），后台线程连接，成功后再填充内容。

3. **快速连点 spawn 卡死** — 多个 `Popen` 并发 → Flutter 引擎同时初始化竞争 GPU。修复：串行 spawn 队列，每个子进程连接成功后才发下一个。

4. **串行队列首次等待 10 秒** — `clear()` 写在了 `wait()` 前面，第一个请求自己阻塞自己。修复：交换顺序。

5. **hash 变更检测未拉取新 state** — poll 检测到 hash 变化后调用 `on_change` → `refresh()`，但 refresh 读的是本地 state（从未更新）。修复：`on_change`/`_refresh` 中先 `get_state()` 拉取最新数据再刷新 UI。同时抑制每秒 hash 请求日志刷屏。
